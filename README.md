I'm a software-focused engineer with a background that spans hands-on technical work, engineering support, software quality, automation, project leadership, operations, and people management. I build practical tools, systems, and workflows that make technical work more reliable, repeatable, and easier to scale.

My current interests are especially centered on **AI-assisted software engineering**, **developer productivity**, **automation**, **software quality**, **systems integration**, and the boundary between software and real-world hardware.

## What I Build

- Test and quality automation

- Experiments that turn interesting technical problems into working software

## Featured Projects

### [Eric's Engineering Constitution](https://github.com/esanacore/engineering-constitution)
An open-source engineering framework for disciplined AI-assisted software development across coding agents, testing, documentation, architecture, security, CI, and release discipline. Includes bootstrap tooling, governance checkers, agent integrations, reusable templates, an MCP server, and a growing project wiki.

### [DevLaunchpad](https://github.com/esanacore/DevLaunchpad)
A Microsoft PowerToys Command Palette extension for managing developer workflows. It discovers Git repositories, surfaces branch and stack information, launches development tools and local services, supports custom commands, and can synchronize GitHub repositories in bulk.

### [SSH Device Manager](https://github.com/esanacore/SSH_DeviceManager)
A practical tool for organizing and accessing SSH-managed devices, reflecting my interest in infrastructure, remote systems, and small utilities that remove friction from technical work.

### [ISTQB Quiz Simulator](https://github.com/esanacore/istqb-quiz-simulator)
A software-testing study and simulation tool built around structured question practice, combining my software engineering work with a long-running focus on quality and verification.

## Engineering Approach

I like software that is useful in the real world, not just technically interesting. My projects tend to emphasize:

- clear architecture and documentation
- automated testing and repeatable workflows
- maintainability and operational awareness
- thoughtful use of AI coding agents without giving up engineering discipline
- practical interfaces between software, hardware, infrastructure, and people

That philosophy is formalized in [Eric's Engineering Constitution](https://github.com/esanacore/engineering-constitution), which I use as a reusable standard across my own projects.

## Background

My path into software engineering was not a reset from another career. I've been doing technical work since I was young, including RF/electronics work early in my career, and later held successful roles in departmental management, operations management, project management, and retail/store management.

That mix matters to how I work today: I care about the code, but I also think about users, operations, schedules, risk, maintainability, communication, and whether a solution actually improves the system around it.

## Education

I'm completing a **B.S. in Computer Science** with a **Project Management for STEM minor** at Southern New Hampshire University.

My coursework has covered algorithms and data structures, databases, software security, test automation and QA, mobile development, full-stack development, operating platforms, applied linear algebra, intelligent agents, systems analysis and design, and the software development lifecycle.
